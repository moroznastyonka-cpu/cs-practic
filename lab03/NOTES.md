it diff показывает различия между версиями, только строки (+ и -).
git show показывает один коммит: кто, когда, что изменил.
git log список коммитов, с --stat добавляет статистику по файлам.

git log -S"def" ищет коммиты, где менялось количество "def". У меня ничего не нашёл, потому что функций в calc.py нет.

git blame показывает по каждой строке файла, каким коммитом она добавлена.
У меня: строки 1-4 коммит 703eaa3 (сложение), строка 5 789ec68 (вычитание), строки 6-8 a405e9f (умножение).



git restore lab03/calc.py вернул файл к состоянию последнего коммита (HEAD), затерев мои локальные правки (я удалила строки умножения, они вернулись).

git restore --source=HEAD~2 lab03/calc.py вернул версию файла из коммита двумя шагами назад (на момент вычитания, без умножения). Проверила через git diff: умножение пропало.

Разница: без --source берётся HEAD, с --source=<коммит> любой указанный коммит. Мои незакоммиченные правки в обоих случаях теряются безвозвратно — если бы они были нужны, пришлось бы сначала сделать git stash или коммит.



Я добавила в calc.py деление без проверки деления на ноль и закоммитила (00e9ba1).

git revert HEAD создал новый коммит (41443f9), который отменяет изменения из 00e9ba1. При этом сам коммит с ошибкой остался в истории, этовидно через git log.

Отличие от git reset --hard: reset передвигает указатель ветки назад и удаляет коммиты из истории (переписывает её). revert наоборот ничего не удаляет, а добавляет новую «обратную» запись.

Почему revert безопаснее в опубликованной истории: если коммит уже был отправлен в общий репозиторий, reset сломает историю у других людей (у них будут конфликты и «не тех» коммитов), а revert просто добавляет ещё один коммит, а история остаётся линейной и непротиворечивой.




Поставила тег v1.0 на текущий коммит командой:
git tag -a v1.0 -m "Рабочая версия калькулятора"

Проверила: git tag показывает v1.0, git show v1.0 показывает метаданные тега и коммит, на который он указывает.

Чем тег отличается от ветки:
Тег -это постоянное имя для конкретного коммита, не двигается.
Ветка - это подвижный указатель, перемещается при новых коммитах.
Тег удобен, чтобы отметить релиз или рабочую версию. Ветка -для продолжения работы.



Рискованную правку делают не в main, а в отдельной ветке.

git switch -c experiment создаёт ветку experiment и переключается на неё.
В ветке я добавила в calc.py безопасное деление (с проверкой деления на ноль) и закоммитила как "Add safe division" (7710ad3).

git switch main вернулась в main.
git merge --no-ff experiment влила ветку experiment в main, создался merge-коммит a9f6f15. Флаг --no-ff оставляет явный след слияния.
git branch -d experiment удалила ненужную ветку (коммиты остались в истории main).

Если бы эксперимент не удался, я могла бы просто удалить ветку, не сливая, и main осталась бы нетронутой.
